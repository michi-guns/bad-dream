# Technology experiments contract

Protocol: `chapter-technology-experiments` 1.0.0. Status: draft.

Purpose: answer bounded technical questions. Inputs are an explicit question,
baseline, constraints and measurable criteria. Excludes selecting an engine,
provider or production architecture merely by creating this chapter.

Define method and measurements before running a trial; record environment,
observations, result and limitations. Distinguish predictions from measured
results. Outputs are reproducible experiment notes, evidence and a decision or
proposal to reconsider. Quality means an appropriate baseline, honest failed or
inconclusive results, bounded cost and an explicit next action.

Use [the optional experiment template](../templates/technology-experiment.md).
Link to horror-study hypotheses when applicable. Technical performance alone
cannot prove player value. Task candidates name a question, session-sized scope,
baseline and verifiable evidence to retain. Accepting the research does not
accept its potential feature. This contract remains draft for creative project
use until reviewed; bootstrap verification exercises it only in disposable data.
